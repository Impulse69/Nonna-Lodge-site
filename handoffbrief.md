# Handoff: Nonna Lodge website

Continuing work on a Next.js marketing site for Nonna Lodge, a boutique hotel in
Aduamoa-Kwahu, Ghana. Built by another Claude Code session (remote/web); picking
up locally now so we can work with local video files directly.

**Repo:** Impulse69/Nonna-Lodge-site — **branch:** `claude/adoring-albattani-iwpbhe`
**Live:** nonna-lodge-site.vercel.app (auto-deploys on push to this branch)

## Stack
Next.js 16 (App Router), TypeScript, Tailwind CSS v4 (CSS-first — theme tokens
live in `src/app/globals.css` under `@theme`, there is **no** `tailwind.config.js`),
React 19. Fonts are self-hosted via `@fontsource` (Cormorant Garamond for
headings/serif, Inter for body/sans) — not loaded from Google Fonts CDN.
Icons: `lucide-react` (note: v1.18 dropped brand icons like Facebook/Instagram/
Twitter — social links render as plain text pills, not icons).

## Design conventions (follow these)
- **Content is data-driven** — copy/prices/contact info lives in typed objects
  under `src/data/`, not hardcoded in JSX.
- **SmartImage pattern**: `src/components/ui/SmartImage.tsx` — if an image's
  `src` is empty, it renders a labelled placeholder instead of breaking; once a
  real path is filled in, it renders via `next/image`. Every image slot in
  `src/data/` has an `alt` describing what it should show.
- **Server Components by default.** Only `"use client"` where interactive:
  Header/MobileMenu, GalleryGrid, ContactForm, HeroVideo.
- **Mobile-first is an explicit priority** the client set. Desktop/tablet
  (≥768px) defaults to a compact 90% scale via `zoom: 0.9` on `body` (client's
  aesthetic preference); phones stay at 100%.
- Always verify with `npm run lint && npm run build` clean before calling
  something done. Ideally spot-check in the browser too.

## Images
114 real hotel photos were supplied, optimized (222MB → ~20MB WebP), and each
one placed in a context that matches what it shows (not decorative filler).
21 fill specific section slots (hero, rooms, dining, reception, etc., defined
in `src/data/images.ts`); the other 93 populate the filterable gallery
(`src/data/gallery.ts` — auto-generated by a one-off script, categorized
exterior/room/dining/interior). Coverage is enforced: every image file is
referenced, no empty `src` slots, no broken paths.

## Active task: video heroes + the full commercial
The client gave a 90-second, 216MB commercial video. Plan agreed with the user:

1. **Crop it into short clips** for background heroes on Home, Rooms,
   Experiences, and Dining pages (in progress — the user is cropping locally).
2. **Put the full 90s commercial in the Gallery page hero** (not yet built).

**Already built** (pushed, live): `src/components/ui/HeroVideo.tsx` — a poster
image with an autoplaying, muted, looping video layered over it, but **only on
tablet/desktop (≥768px) with no-reduced-motion**. Phones get just the poster —
zero video bytes downloaded on mobile, keeping it fast. Wired into
`Hero.tsx` (home) and the shared `PageHeader.tsx` (Rooms/Experiences/Dining).

**Waiting on:** drop compressed clips into `public/videos/` named exactly
`hero-home.mp4`, `hero-rooms.mp4`, `hero-experiences.mp4`, `hero-dining.mp4` —
they'll activate automatically (poster shows until then, verified working).
Compression recipe (ffmpeg, target 3–8MB/clip, strips audio since heroes are
muted) is in `public/videos/README.md`.

**Not yet decided — needs a call before building the Gallery hero:**
- The full 90s commercial should **not** be a silent autoplay loop like the
  others (defeats the point of a commercial nobody can hear, and it's heavy).
  Two options discussed: (A) click-to-play poster that plays *with sound* when
  clicked — near-zero load cost, recommended; or (B) silent background loop
  for visual consistency, at the cost of no sound.
- Where the full video lives: **self-hosted** (compress to ~20–30MB, commit to
  repo — GitHub hard-rejects anything over 100MB) vs. an **external host**
  (YouTube unlisted / Vimeo — adaptive quality, better for slow mobile
  connections, small amount of platform branding in the player).

Resolve these two questions with the user, then build the Gallery hero
click-to-play (or loop) treatment to match.

## Gotchas hit so far (don't re-discover these)
- `create-next-app` rejects directory names with capital letters as the
  package name — irrelevant now since the repo already exists.
- GitHub hard-rejects files >100MB — compress before committing any video.
- Next 16 + eslint-config-next added a `react-hooks/set-state-in-effect` rule
  that flagged a naive `useEffect(() => setOpen(false), [pathname])` pattern —
  moved the state reset to the click handlers instead.
- Keep Vercel's built-in image optimizer on — don't switch to static export
  (`output: 'export'`) or `next/image` optimization breaks.
